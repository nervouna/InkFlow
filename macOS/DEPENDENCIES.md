# Runtime dependencies

`macOS/scripts/dependencies.sh` pins source URLs and SHA-256 digests. Archives live only in ignored `build/deps`. No dependency manager or network connection is used by the installed app.

- librime 1.17.0, upstream revision `33e78140250125871856cdc5b42ddc6a5fcd3cd4`: official universal macOS binary. BSD license in `Licenses/librime.txt`. The main release dylib links only macOS system libraries. Its plugin loader discovers dynamic plugins in the sibling `rime-plugins` directory.
- librime-lua: the universal `rime-plugins/librime-lua.dylib` from the same checksum-pinned librime archive, bundled under `Contents/Frameworks/rime-plugins`. It links the bundled librime and macOS system libraries, with Lua 5.4.8 embedded in the plugin. No other release plugins are bundled. `install.sh` signs both dylibs before signing the application. The [plugin BSD license](https://github.com/hchunhui/librime-lua/blob/master/LICENSE) and [Lua 5.4.8 MIT license](https://github.com/lua/lua/blob/v5.4.8/lua.h) ship in `Licenses/librime-lua.txt` and `Licenses/lua.txt`.
- rime-pinyin-simp revision `0c6861ef7420ee780270ca6d993d18d4101049d0`: complete upstream `pinyin_simp.dict.yaml`, derived from Android PinyinIME. Apache-2.0 license in `Licenses/pinyin-simp.txt`.
- [rime-easy-en](https://github.com/BlindingDark/rime-easy-en/tree/54a4a07289412efc54134092c0d945f895a71ed3) revision `54a4a07289412efc54134092c0d945f895a71ed3`: the complete, unmodified `easy_en.dict.yaml` remains in `build/deps` as input to the shared admission policy. The generated, filtered English and mixed dictionary sources ship in `Resources/Rime`, with their generated status and upstream attribution in the headers. Upstream LGPL-3.0 and the incorporated GPL-3.0 text ship in `Licenses/easy-en-LGPL-3.0.txt` and `Licenses/easy-en-GPL-3.0.txt`. No upstream Lua filters or sentence splitters are used.
- `schemas/inkflow_pinyin.schema.yaml` adapts the upstream schema for one full-pinyin mode. Stroke reverse lookup and external symbol presets are omitted; punctuation and paging bindings are explicit. The original Chinese dictionary is copied unmodified.

English uses the Lua plugin bundled from the pinned librime release. `schemas/lua/inkflow_english.lua` looks up the admitted, compiled `easy_en` dictionary through `Memory`, then sorts all matching exact words and completions by effective source weight. Equal weights prefer the exact case-sensitive text, then bytewise lexical order; duplicate text keeps its highest weight. One- and two-letter inputs return exact admitted English words only, including `a` and `i` → `I`. Longer prefixes look up every admitted matching entry and cache only the current input, avoiding both length-first truncation and an unbounded input history. The API is documented in the [official Lua bindings](https://github.com/hchunhui/librime-lua/blob/master/contrib/librime.lua) and verified by the bundled-runtime regressions. The compilation-only `easy_en` schema keeps literal English spelling independent of Pinyin algebra.

InkFlow prioritizes Chinese input; mixed composition serves occasional English words within Chinese text. `macOS/scripts/prepare-rime.sh` applies one build-time admission gate to every English source record and generates `easy_en.dict.yaml`; it then derives `inkflow_mixed.dict.yaml` only from that admitted output. Build-time policy is maintained in [`macOS/config/english.conf`](config/english.conf): `ENGLISH_MIN_SOURCE_WEIGHT=990000` and `MIXED_ENGLISH_WEIGHT_DIVISOR=100`. These are empirical defaults, not calibrated corpus frequencies. Edit the source configuration and rebuild to change them; there is no GUI or runtime setting.

[`macOS/config/english-boosts.tsv`](config/english-boosts.tsv) maintains zero-weight corrections separately from the generator: exact displayed spelling, replacement source weight, and reason, separated by tabs. Corrections apply only to existing zero-weight records (a missing weight is also treated as zero), never create new words, and never override a nonzero source weight. A correction applies to the existing code aliases of that exact displayed spelling, without inferring capitalization or plurals. Every record, including aliases and case variants, must then have effective weight greater than or equal to the common minimum. No exact-input, uppercase, paging, or low-Chinese-candidate-count bypass exists.

Standalone English retains the admitted effective weights without scaling. Mixed composition additionally requires literal alphabetic text equal to its code and at least four letters; its weights are the effective weights divided by the configured divisor and truncated to integers. It imports the original Pinyin dictionary. `inkflow_mixed.schema.yaml` compiles it with Pinyin algebra but adds no selectable mode. Invalid numeric settings, malformed correction records, and duplicate correction spellings fail the build before replacing either runtime dictionary; there is no fallback to the complete source. Empty correction files and policies admitting no English records are valid.

The default correction list contains `email`, `Email`, `emails`, and `Emails`, each with effective English weight 990000 and mixed weight 9900. The defaults admit 16,810 English records and retain the previous 9,858 mixed records from the pinned source. Raising the threshold above a correction weight excludes that word from both dictionaries; changing the divisor affects only mixed weights. `women`, `WOMENS`, `womenfolk`, `tameness`, `Nimes`, `nimetti`, `nimetz`, `Haiti`, `Haitian`, `Haitienne`, `haitians`, and `compute` fail the default gate even on exact input. `offer` and `computer` remain; typing `compute` may complete to `computer`. Admitted `actual` and `actually` exercise frequency-before-exactness ordering. High-weight `D` still passes, with Chinese-first ranking protecting `d` → 的. Explicit ASCII mode passes characters through without consulting either dictionary. Broader word cleaning and the quality of upstream weights remain outside this policy.

`schemas/lua/inkflow_mixed.lua` delegates segmentation and sentence generation to Rime's `script_translator`, yielding only complete mixed candidates. For equal input coverage, the priority order is native Chinese, mixed sentences (quality -0.5), then standalone English (quality -1). This uses the [pinned engine's candidate comparator](https://github.com/rime/librime/blob/33e78140250125871856cdc5b42ddc6a5fcd3cd4/src/rime/candidate.cc), which compares covered input length before quality. A Chinese candidate that interprets an unfinished final Pinyin syllable still counts as full coverage. Consequently `email` follows `额买了`, and `我发了email` follows `我发了额买了`; both English candidates remain selectable and commit their exact text. A complete English/mixed candidate can still lead a shorter Chinese translation, as in the offer examples. Cross-language demotion applies to the entire English stream, preserving source-frequency ordering within it, including frequent completions ahead of an exact word.

The primary Chinese translator and `pinyin_simp.userdb` stay independent and unchanged; supplemental English and mixed translators disable user learning. This preserves existing user dictionaries without migration. The coverage rule expresses a Chinese preference and does not estimate whether a Chinese interpretation sounds natural. Regression transcripts cover every prefix and backspace of ordinary Chinese sentences, mixed offer/email/office boundaries, source-weight ranking, case/ties, ambiguous English reachability, selection, paging, editing, and ASCII passthrough.

The native app targets this Apple Silicon Mac. Its minimum deployment target is macOS 26. Build uses the current Xcode SDK, Swift 6, ARC, and warnings as errors. InputMethodKit controls the candidate UI. Each controller owns one Rime session, and the process initializes/deploys the engine on the main thread before serving input. Startup requests Rime's full maintenance check, bypassing the timestamp-only early exit: a newly installed bundle may have been built before the user's latest deployment. Rime's [dictionary compiler](https://github.com/rime/librime/blob/33e78140250125871856cdc5b42ddc6a5fcd3cd4/src/rime/dict/dict_compiler.cc) compares content checksums and reuses unchanged compiled tables. The deployment regression upgrades an existing full-English cache using older resource timestamps, verifies admission, and checks unchanged table bytes/mtimes and Chinese user-dictionary preservation on restart. Deployment and user dictionaries are writable only in Application Support/InkFlow. Routine logs omit input text.

The app icon is built from the approved inkstone and brush artwork in `Design/AppIcon`; see its README for source and export roles. The menu icon uses Ink lettering in Futura Bold in `Resources/MenuIconTemplate.tiff`, with 1x/2x representations; its generator and design notes live in `Design/MenuIcon`. Parent input-source and palette icons still use the local macOS CoreTypes generic application icon. The bundle identifier includes `.inputmethod.` for macOS input method discovery/launch compatibility. `register.sh` verifies TIS registration after installation without enabling or selecting the input source.

A single explicit `.Hans` input mode exposes the existing simplified pinyin engine to system settings. Its name is localized through `InfoPlist.strings`. Registration first informs Launch Services, then TIS, and requires a named/select-capable keyboard mode. A separate `--verify-enabled` invocation reads the parent and mode enabled states; registration never enables or selects a source. Mode metadata follows Apple's TN2128 and the current TextInputSources/TextServices SDK headers.
