# Project guidance

1. For known failures, read [macOS/DEBUGGING.md](macOS/DEBUGGING.md), preserve the incident, verify current official/upstream behavior, and reproduce with the running engine or smallest native probe. Classify evidence as source, configuration, InkFlow, platform, or test-environment behavior. API names, simulated clients, and timing correlation prove neither behavior nor cause.
2. Preserve offline Rime as baseline. Optional AI, downloads, telemetry, and recovery must not block or corrupt it; keep network, disk, SQLite/JSON, and long preparation off the key-event path.
3. Candidate/dictionary consumers share one reproducible generated-data contract with explicit admission, ranking, deduplication, and source priority. Missing evidence is `unknown`, never zero or success.
4. Telemetry must not silently change ranking/input. Multi-stage/module/network features retain correlation IDs, stages, timing, and skip/cancel/failure reasons while suppressing repeats. Log no secrets/user content; store only minimal, bounded, local data with explicit retention; keep AI default-off and networking local-first.
5. Report source/tests, build/bundle, signature, installation, registration/enablement, process, native harness, real-client typing, notarization, and publication separately. Distinguish first install, update, temporary diagnosis, formal daily-use installation, and release. One does not prove another; record visible typing only after user confirmation.
6. Use [inkflow-mixed-input-maintenance](.agents/skills/inkflow-mixed-input-maintenance/SKILL.md) for mixed input, English admission/ranking, or frequency overrides; [inkflow-quality-analysis](.agents/skills/inkflow-quality-analysis/SKILL.md) for recorded quality evidence; and [inkflow-release](.agents/skills/inkflow-release/SKILL.md) for GitHub release or interrupted publication.
7. Put additional worktrees under the main checkout's `.worktrees/<name>/`; keep `/.worktrees/` ignored. Before edits/integration, check cwd, branch, ownership, and dirty state. Preserve concurrent work, stage only authorized files, and test the exact prospective integration tree. Remove only proven task-owned failed experiments/temporary artifacts. Merge, push, tag/release, install, and cleanup remain separate.
8. Follow [macOS/DEVELOPMENT.md](macOS/DEVELOPMENT.md#verification) for selection and prerequisites. Daily work uses affected tests plus required related-module, resource, and targeted native/GUI checks; documentation uses scoped review and diff checks. Formal installation/release requires the documented full regression, GUI sequence, and applicable release checks. Report missing, failed, blocked, or skipped checks.
